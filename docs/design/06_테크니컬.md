# 06. 테크니컬 디자인 직군 의견서 (UE5)

> 전제: UE 5.3~5.5대 기준. Motion Matching / StateTree / MetaSounds는 버전별 정식/실험 단계 상이 → 착수 시점 엔진 버전을 먼저 고정하고 production-ready 여부 재확인.

## 1. 아키텍처 — GAS 채택 여부 / Enhanced Input

**GAS: 부분 채택, 전면 의존 반대.** 선형 싱글이라 GAS의 핵심 가치(복제·예측)는 회수율 낮고 학습/디버깅 비용 큼(초기 6~8주 인프라 배선 소진 위험). **권장: GameplayTag + GameplayEffect 개념만 차용.** 이동 상태(달리기/슬라이딩/거치/포복)·무기 상태(장전/잼/조준)·피격/억압 같은 "동시에 켜지는 다수 플래그"는 GameplayTag 컨테이너로 → 입력 게이팅·애님 분기·AI 인지 일관 처리. HP/탄약 단순 수치는 일반 C++/BP 컴포넌트. (팀에 GAS 숙련자 1명+ 있으면 풀 GAS도 합리적 — 팀 역량 의존.)

**Enhanced Input(적극 채택):** 상태별 IMC 레이어링(`IMC_Default`/`IMC_Mounted`/`IMC_Scoped`/`IMC_Prone`, push/remove). **수동 배제(기둥4)·R 재장전(기둥3)은 분리하되 상황별 같은 키 재맵핑** (잼 상태에서 R=재장전이 아닌 노리쇠 후퇴/배출). HUD 최소화라 입력 수신은 반드시 애니/사운드/햅틱으로 "수신됨" 표시.

## 2. 무기 시스템 — 데이터 주도 설계

K-13/K-5/픽업으로 늘어나므로 하드코딩 금물. **`UDataAsset` 기반 무기 정의**(발사모드·연사·반동 커브·탄창·잼 기본확률·몽타주·사운드뱅크). 무기 클래스는 "데이터 해석 런타임"으로 얇게.

**사격:** 히트스캔 기본(현대전·선형에서 발사체 시뮬은 과투자).

**무기 FSM (기둥4):** `Ready→Firing→(Cycling)→Ready` + 분기 `Empty`/`Reloading`/`Jammed`/`Clearing`. 잼 트리거는 매 cycle 종료 시 확률 롤(단, **누적·조건부 확률** — 연사시간·과열/오염·픽업 노후도·환경 태그 가중, 데이터 커브로 디자이너 노출). 잼 종류 분기는 MVP 1종(노리쇠 후퇴 해소)부터, 검증 후 확장.

**충돌 주의:** 무알림 탄 소진(기둥2)과 잼 둘 다 "갑자기 안 나감" → 공이 빈 클릭음 vs 걸림 둔탁음을 명확히 차별화하는 **오디오 설계가 성패 좌우.**

**픽업:** 같은 DataAsset 인터페이스 → 동일 파이프라인. 적 무기는 탄약 호환성·노후도(잼↑)로 차별화.

## 3. 비-HUD 피드백 기술 구현

- **HP — 포스트프로세스 머티리얼:** 가장자리 비네팅·채도저하·혈류 펄스·청각 필터(저역+이명). `PostProcessVolume`+Blendable + **MPC(Material Parameter Collection)**로 머티리얼·오디오·카메라 동기화. 회복 시 보간 필수.
- **MetaSounds:** 비-HUD 정보의 절반 담당. 무기 상태(빈 클릭/걸림/마지막 몇 발 톤 변화)·체력 단계 호흡/심박·탄창 무게감 절차적 구동. "마지막 3발 음색 변화"는 강력한 디제시스 잔탄 힌트.
- **카메라 셰이크:** 반동·피격·폭발. 과하면 멀미/정보 가림 → 강도 옵션.
- **햅틱:** 게임패드/듀얼센스/Steam Deck. **키마 유저엔 없으므로 필수 채널 금지(보조만).**
- **접근성 안전장치:** "보조 HUD 토글"을 기술적으로 미리 분기 가능하게 설계(Steam 리뷰·심의 리스크 완화).

## 4. 이동·컨텍스트 액션

**Motion Matching vs ABP:** Motion Matching(Pose Search)은 강력하나 버전별 Experimental/Beta + 대량 데이터·메모리·인력 요구 → **소규모 팀 1순위 채택은 리스크.** 권장: **전통 ABP+Blend Space 기본**, 이동 품질이 핵심 차별점이면 PoC 후 부분 도입. 어느 쪽이든 상위 상태는 ABP 밖(FSM/GameplayTag)에서 결정, ABP는 "그리기만".

**이동 상태:** CMC 기본으로 대부분 커버. **슬라이딩·거치·엄폐 부착은 CMC에 없어 커스텀** 필요(슬라이딩=타이밍 윈도우+마찰/속도 커브).

**컨텍스트 감지:**
- 거치: 전방·하단 트레이스로 엣지 감지 → IMC 교체+이동 잠금+반동 감소, 표면 정렬 IK.
- 엄폐: **자동 트레이스는 오작동 잦음** → 선형 이점 살려 **레벨 디자이너가 cover 지오메트리/볼륨 명시 배치**(하이브리드, 비용↓ 안정성↑).
- 포복: 캡슐 리사이즈 + 천장 클리어런스 트레이스(끼임 버그 방지).
- 모든 컨텍스트는 GameplayTag 표기 → 입력 게이팅·AI 인지 공유.

## 5. AI 기술

**StateTree 1순위**(버전 성숙도 확인). 엄폐 활용+무기 픽업+억압 반응 등 상태·조건 분기 명확 → 잘 맞음. 팀이 BT 익숙하면 BT+Blackboard도 충분(선형이라 규모 작음).
- **AI Perception:** 시각(시야각·LoS)·청각(사격음·발소리, 무알림/사운드 설계와 직접 연동)·피해. 적 인지 상태를 **애니/콜아웃으로 디제시스 노출**해 플레이어가 "들켰는지" 읽게(중요).
- **엄폐 활용:** EQS로 "LoS 차단+사격 가능 위치" 질의(빈도·후보 제한).
- **무기 픽업 AI:** 임팩트 크나 후순위(MVP 제외 가능), DataAsset 재사용.
- **억압 반응:** 근접 탄착에 엄폐 후퇴 → 무알림 사격의 영향 가시화.

## 6. 스코프·리스크·성능 (소규모 팀)

**MVP:** 데이터주도 무기 2종, 잼 1종(노리쇠 해소), 무알림 탄 소진, 무한 재장전, HP 포스트프로세스+오디오, 이동 6~7종, BT/StateTree 전투 AI 1~2종, 선형 레벨 1개(버티컬 슬라이스).
**2차:** 잼 다양화·적 무기 픽업·Motion Matching PoC·고급 엄폐 AI·햅틱.
**주의(일정 블랙홀):** 풀 GAS, 전면 Motion Matching, 자동 엄폐 트레이스, 다종 잼 동시 출시.

**성능:** 상시 포스트프로세스 비용 예산 초반 확정. Lumen/Nanite는 욕심 따라 결정하되 **저사양 폴백**을 처음부터(선형 레벨은 컬링·프리컴퓨트 유리). `Insights`/`stat unit`/GPU 프로파일 마일스톤마다.

**Steam:** Steamworks SDK(`Online Subsystem Steam`)·도전과제·클라우드세이브·Steam Input. Deck Verified 목표 시 입력 프롬프트 아이콘 대응. 셰이더 사전컴파일로 첫 실행 끊김 완화, 연령 심의(전쟁·폭력), 빌드 안정성(환불 정책 고려).

## 7. 리스크 / 열린 질문

1. 무알림 탄 소진 vs 잼 구별 가능성 — 오디오 차별화 PoC 최우선.
2. HP 미표시 공정성 — 포스트프로세스 강도 곡선 데이터화로 빠른 반복.
3. 접근성/보조 HUD 토글 — 강력 권장하나 정체성과 충돌(기획 결정).
4. GAS 채택 범위 — 팀 숙련자 유무에 의존.
5. 엔진 버전 고정 — Motion Matching/StateTree/MetaSounds production-ready가 버전 종속.
6. 이동 품질이 차별점인가? — Motion Matching 투자 여부 결정.
7. 잼 깊이 — 1종 충분 vs 다종이 핵심 재미? 기둥4 야심 수준이 스코프 확정.
